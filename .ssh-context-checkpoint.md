## PHASE 3: DESIGN CLEANUP

### User's Core Concern:
"packet format does not depend on cipher type and should be handled outside"

### Current Architecture:
1. **SshCipher.encrypt(packetBytes)**: encrypts [4-byte pktLen||packet] → [4-byte pktLen||ct||tag]
   - Cipher knows pktLen is first 4 bytes, uses it as AAD
   - Cipher outputs pktLen in plaintext in result
   
2. **SshCipher.decrypt(data)**: receives [ct+tag] → [4-byte pktLen||packet]
   - Cipher reconstructs pktLen in plaintext
   
3. **SshTransportCodec.decode(wireData)**: strips tag, decrypts, parses [pktLen][padLen][payload][padding]
   - Codec parses packet format from decrypted data

### Design Violation:
Cipher knows about pktLen placement (4 bytes at start). The user wants:
- Cipher.encrypt(rawPacket) → ciphered data (no pktLen awareness)
- Cipher.decrypt(cipheredData) → raw packet (no pktLen awareness)
- Codec handles: pktLen encoding/decoding, MAC/tag, padding

### What Needs to Change for AEAD:
1. **Cipher.encrypt(packet)**: encrypts just the packet → [ciphertext][tag]
2. **Cipher.decrypt(data)**: receives [ciphertext][tag] → decrypted packet
3. **Codec.encode(payload)**: adds pktLen + padding → packetBytes → cipher.encrypt()
4. **Codec.decode(wire)**: for AEAD:
   - Strip tag → [ct]
   - Parse wire first 4 bytes as pktLen (plain) → AAD
   - cipher.decrypt(ct) → [pktLen||packet]
   - Parse [pktLen][padLen][payload][padding]

### What Needs to Change for Non-AEAD (CTR):
Currently correct: codec handles MAC, cipher just decrypts. No changes needed.

### Action Plan:
1. Modify SshCipher interface to NOT know about pktLen
2. Modify Aes256Gcm.encrypt(): no longer copies pktLen, just [ct][tag]
3. Modify Aes256Gcm.decrypt(): no longer reconstructs pktLen, just decrypted bytes
4. Modify SshTransportCodec.decode(): handles pktLen splitting for AEAD
5. Modify SshTransportCodec.encode(): wraps packet with pktLen before cipher.encrypt()

### AEAD Changes Detail:

**Cipher.encrypt():**
- Input: [pktLen||packet] (from codec)
- AAD: first 4 bytes (pktLen)
- Encrypts: data[4:] → [ciphertext][tag]
- Output: [ciphertext][tag] (no pktLen prefix!)

**Cipher.decrypt():**
- Input: [ciphertext][tag] (from codec)
- AAD: [pktLen] (4 bytes, passed separately or stored)
- Decrypts: ct → [pktLen||packet]
- Output: [pktLen||packet] (reconstructed)

Wait — but codec needs to know pktLen to pass it as AAD. So codec must extract pktLen from wire first, then pass:
- codec.decode(wire): wire = [4-byte plain pktLen][ct][tag]
  - Extract pktLen from wire[0:4]
  - Strip to get ct+tag: wire[4:]
  - cipher.decrypt(ct+tag, aad=pktLen) → [pktLen||packet]
  - Parse packet format

For this, we need to pass AAD separately to the cipher. Current cipher interface doesn't support AAD.

### Option: Add getAAD() to Cipher interface?
No — AAD is the 4-byte pktLen. The cipher doesn't need to know about it.
Codec handles AAD extraction and passes it to cipher.

### Revised Cipher interface:
```java
interface SshCipher {
    byte[] encrypt(byte[] plaintext);
    byte[] decrypt(byte[] ciphertextWithTag);
    // AAD is handled by codec, not cipher
}
```

For AEAD:
- Codec extracts AAD (4-byte pktLen) from wire
- Codec calls cipher.decrypt(ciphertextWithTag)
- Cipher internally uses stored AAD from previous setAAD() call? No...

Actually, the cleanest approach:
- Codec sets AAD on cipher via setAAD(aadBytes) before decrypt/encrypt
- Or: Codec passes AAD to encrypt/decrypt methods
- Or: Cipher.encrypt(data) where data = [pktLen||packet], uses data[0:4] as AAD
  - This is what the current implementation does

But the user says "packet format does not depend on cipher type". If we use the approach where:
- Cipher.encrypt(plain) → ct+tag (no pktLen awareness)
- Cipher.decrypt(ct+tag) → plain (no pktLen awareness)

Then we need to pass AAD separately:
```java
byte[] encrypt(byte[] plain, byte[] aad);
byte[] decrypt(byte[] ctWithTag, byte[] aad);
```

This separates packet format from cipher.

### Implementation Plan:
1. Add setAad(byte[] aad) to SshCipher interface
2. Aes256Gcm.encrypt(plain): plain = [packet], AAD is [pktLen] (4 bytes, set via setAad)
   - Wait, but codec doesn't know pktLen before encryption...
   
Actually for encryption:
- Codec knows payload
- Codec adds pktLen + padding → packetBytes
- Codec strips pktLen: packetBytes[4:] → to be encrypted
- Codec stores pktLen: packetBytes[0:4] → to be AAD
- codec.setAad(pktLenBytes)
- codec calls cipher.encrypt(packetBytes[4:]) → [ct][tag]
- codec prepends pktLen: [pktLen][ct][tag] → wire

For decryption:
- Codec reads 4-byte plain pktLen from wire
- Codec calls codec.setAad(pktLenBytes)
- Codec strips tag: [ct]
- codec calls cipher.decrypt(ct) → [packet]
- Codec parses [packet] → payload

This way, cipher never sees pktLen in its input/output. Pure data transformation.

3. Aes128Gcm.java: same
4. SshTransportCodec.encode(): strip pktLen, set AAD, encrypt remaining
