# Lego Flow — Code Review & Improvement Plan

**Date**: 2026-10-31
**Branch**: cleanup-messaging
**Commit**: 921ae594

---

## Executive Summary

Lego Flow is a mature composable data processing framework with **8,582 tests** across **42 leaf modules**, **2,022 source files**, and **1,307 test files**. The project demonstrates strong protocol accuracy discipline, comprehensive interop test infrastructure, and good assertion quality. However, there are systemic issues in test timing (Thread.sleep), coverage gaps, and interop test grouping that need attention before production readiness.

## Strengths

### 1. Protocol Accuracy Discipline
- Comprehensive `AGENTS_protocol_accuracy.md` with 12 rules
- Golden byte tests for protocol codecs (Kafka: 35 codecs fully tested)
- `AmqpEventListener` pattern for test synchronization
- In-memory transport pairs for unit tests

### 2. Test Quality
- **25,705 AssertJ assertions** — strong use of specific matchers
- Only 0 bare `isTrue()` without context (all are enum transition tests)
- Good use of `hasSize()`, `contains()`, `startsWith()` for precise assertions
- Protocol flow listeners with `latchOnFirst()` factory for testing

### 3. Interop Test Infrastructure
- Docker Compose for 4 reference servers (nginx, Mosquitto, Redis, PostgreSQL)
- Maven-based with `interop.group` property for parallel execution
- `failIfNoTests=true` guard against tag typos
- 20 interop test files covering 15+ protocols

### 4. Documentation
- 65 doc directories with ARCHITECTURE.md, REQUIREMENTS.md, COMPLIANCE.md
- Module-specific AGENTS.md (71 modules)
- Root AGENTS.md with cross-references
- Test patterns and protocol accuracy documentation

### 5. Architecture
- Transport-agnostic core via `DataChannel` SPI
- Dual API (sync + async CompletableFuture)
- Virtual thread support for blocking I/O
- In-memory transport for unit tests

## Problems Identified

### 1. Interop Test Grouping — Incomplete

**Current state**: 4 groups defined but not all tests are tagged.

```
interop-rest:      14 tests
interop-messaging-core: 4 tests
interop-kafka:     1 test
interop-wamp:      1 test
mqtt-v5:           1 test
```

**Issues**:
- Some interop tests reference `interop.group` in comments but lack `@Tag` annotations
- `mqtt-v5` tag exists but no test uses it
- Group distribution is uneven (14 vs 1 tests)
- No `doc/ci-groups.md` documenting group purposes

**Impact**: CI cannot run specific interop groups reliably.

### 2. Coverage Below Target

**Current**: 60% instruction, 43% branch

**Target**: 90%+ for core modules

**Modules likely below 90%** (need verification):
- `lego-flow-network` submodules (DNS, SNMP, syslog)
- `lego-flow-iot` (UPnP)
- `lego-flow-rpc` (GraphQL)
- `lego-flow-demos` (by design, but should be excluded from coverage)

**Root causes**:
- Many modules lack integration tests
- Branch coverage particularly low (43%) — error paths untested
- Some modules have no `COMPLIANCE.md`

### 3. Thread.sleep in Tests — 254 Instances

**Problem**: Timing-dependent tests are flaky and mask real race conditions.

**Examples**:
```java
// messaging/amqp/src/test/java/.../AmqpServiceIntegrationTest.java
Thread.sleep(100);  // Wait for handshake (fixed in this session)

// messaging/mqtt/src/main/java/.../MqttBroker.java
Thread.sleep(timeoutMs);  // Blocking wait in broker

// service/src/main/java/.../InMemoryByteTransport.java
Thread.sleep(Math.min(10, ...));  // Chunked delivery simulation
```

**Root causes**:
- Missing proper synchronization (CountDownLatch, CompletableFuture)
- In-memory transport timing semantics not well-defined
- Virtual thread scheduling races

**Impact**: 22 race/flaky commits in history indicates systemic issue.

### 4. Disabled Tests — 33 Total

**Categories**:

| Category | Count | Examples |
|----------|-------|----------|
| Interop tests (Docker required) | 15 | All @Disabled with clear reasons |
| Flaky timing tests | 4 | MQTT KeepAliveTimeoutTest, InMemoryMqttBridgeTest |
| Environment-specific | 4 | DNS multicast, localhost DNS |
| Unsupported features | 6 | MySQL aggregate queries |

**Actions needed**:
- Interop tests: Document in AGENTS.md, keep disabled
- Flaky tests: Fix root cause or remove
- Environment tests: Add CI notes or fix
- Unsupported features: Document in COMPLIANCE.md

### 5. TODO/FIXME Items — 10 Total

| Location | Count | Issue |
|----------|-------|-------|
| `database/mysql/server/AggregateQueryTest.java` | 6 | Server doesn't support features |
| `network/dns/resolver/RecursiveResolverTest.java` | 1 | Unreachable servers |
| `network/dns/resolver/StubResolverExtendedTest.java` | 3 | Unreachable servers |

**Action**: Either implement or document in REQUIREMENTS.md as out-of-scope.

### 6. Race Conditions — Systemic

**22 commits** related to races/flaky tests indicate systemic issues in:
- Transport layer (InMemoryByteTransport, PipelineByteTransport)
- Service integration tests (AMQP, NATS)
- MQTT broker timing

**Pattern**: Tests call `connect()` before setting listeners, causing missed events.

## Improvement Plan

### Phase 1: Interop Test Configuration (1-2 days)

**Goal**: All interop tests properly tagged and groupable.

**Tasks**:
1. Audit all 20 interop test files for `@Tag` annotations
2. Add missing tags to tests referencing `interop.group` in comments
3. Create `interop-tests/doc/ci-groups.md` documenting groups
4. Ensure `failIfNoTests=true` catches typos
5. Verify CI workflow runs all 4 groups correctly

**Verification**: `mvn verify -pl interop-tests -am -DskipInteropTests=false -Dinterop.group=interop-rest` runs exactly 14 tests.

### Phase 2: Coverage Gap Analysis (2-3 days)

**Goal**: Identify modules below 90% and prioritize improvements.

**Tasks**:
1. Generate per-module JaCoCo reports
2. Identify modules below 90% instruction coverage
3. For each low-coverage module:
   - Check if COMPLIANCE.md exists
   - Check if tests exercise error paths
   - Add integration tests for uncovered branches
4. Exclude `demos` module from coverage gate (by design)

**Verification**: All modules ≥90% instruction coverage (excluding demos).

### Phase 3: Thread.sleep Elimination (3-5 days)

**Goal**: Replace timing-dependent tests with proper synchronization.

**Priority order**:
1. **High**: Tests with `Thread.sleep(100+)` that cause flakiness
2. **Medium**: Tests with `Thread.sleep(5-50)` that could use latches
3. **Low**: Main code `Thread.sleep` (legitimate for demos, protocols)

**Tasks**:
1. Audit all 254 `Thread.sleep` in tests
2. Replace with `CountDownLatch`, `CompletableFuture`, or protocol listeners
3. Fix InMemoryByteTransport timing semantics
4. Document enqueue-only send contract in AGENTS.md

**Verification**: No test uses `Thread.sleep` except legitimate timeout tests.

### Phase 4: Disabled Test Resolution (2-3 days)

**Goal**: All disabled tests either fixed or documented.

**Tasks**:
1. **Flaky tests** (4): Fix root cause or remove
   - `MqttAclTopicTest` — virtual thread race
   - `KeepAliveTimeoutTest` (×2) — timing-dependent
   - `InMemoryMqttBridgeTest` — callback threading
2. **Environment tests** (4): Add CI notes or fix
   - DNS multicast tests
   - Localhost DNS tests
3. **Unsupported features** (6): Document in COMPLIANCE.md
   - MySQL aggregate queries

**Verification**: Only interop tests remain @Disabled.

### Phase 5: Documentation Gaps (1-2 days)

**Goal**: All modules compliant with AGENTS.md requirements.

**Tasks**:
1. Identify modules missing COMPLIANCE.md
2. Add COMPLIANCE.md to modules without it
3. Verify all AGENTS.md reference root AGENTS.md
4. Update REQUIREMENTS.md for any new features

**Verification**: 71 AGENTS.md, 61 COMPLIANCE.md, 63 ARCHITECTURE.md, 63 REQUIREMENTS.md.

### Phase 6: Race Condition Fixes (ongoing)

**Goal**: Eliminate systemic race conditions.

**Tasks**:
1. Review all 22 race/flaky commits for patterns
2. Fix InMemoryByteTransport TCP semantics (done in this session)
3. Fix PipelineByteTransport enqueue-only contract
4. Add protocol flow listener pattern to AGENTS.md (done)
5. Document test synchronization patterns

**Verification**: No flaky test commits in 30 days.
